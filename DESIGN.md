# Portfolio direction

Direction comes from the owner's video reference and approved interactions: a personal developer portfolio with physical doors, a notebook, and a pull-cord theme switch. Keep the existing project content and identity.

Audience: people reviewing Adrian's development work, collaborators, and prospective clients.

Energy 2 / Rhythm 3 / Motion 2. The portrait and notebook introduce Adrian, doors invite inspection, project rows explain contributions, and the contact panel offers a direct next step. Motion responds to interaction; nothing loops automatically.

## Decisions

- Warm paper and dark green preserve the approved studio atmosphere; burgundy remains the primary action accent.
- Four muted door colors identify the four projects. Repeat each door's color only in its own preview image mount, rather than treating every color as a page-wide accent.
- Inter keeps project descriptions readable; condensed lettering is reserved for the existing name mark.
- Preview cards use a paper surface and image mount to distinguish a quick look from the larger, persistent project descriptions below.
- Use actual project screenshots and concise summaries of existing project information. Add no invented statistics, testimonials, or claims.
- Opening a door precedes the card emerging. On departure, the card retracts before the door closes. The animation explains where the preview belongs.
- Allow a short exit grace period so the pointer can move between the door and preview. Open only one preview at a time.
- Preview position stays inside the viewport, including near the first and last doors, and clears the hanging theme switch. Touch uses first tap to preview, then a second tap or card tap to visit. A 44px close button provides a reliable way to dismiss the preview on touch screens.
- Keyboard focus opens the same preview; Escape dismisses it. Reduced motion removes the choreography while preserving the interaction.
- Shadows distinguish the temporary preview from the page beneath it. A single external-link arrow identifies the destination action, and no sparkle is needed in a project preview.

Review reference: [Anti Slop rules](https://github.com/miqdadbadjuber/anti-slop/blob/main/antislop.md). Apply the design, accessibility, and content principles to this work; this repository does not install its CLI or change global agent settings.
